# UX11-STEM — 제시 항목·보조 본문의 줄바꿈

## 사용자 제공 회귀 사례

1. `다음 (가) ~ (라)의 ... 같은 것끼리 묶인 것은? ( ) (가) 만 17세 ... (나) 예금잔액 ... (다) 피상속인 ... (라) 1백만원 ...`: 실제 제시 항목 (가)~(라)를 각각 별도 줄/항목으로 표시한다. 도입부의 범위 참조 `(가) ~ (라)`를 항목 시작으로 잘못 잡지 않는다.
2. `다음 (가)~(라)에 ... ? ( ) - 금융회사가 ... ( 가) 이내 ... - 국내원천소득 ... ( 나)이 ... - 대리인을 ... ( 다)이다. - 정액적립식 ... ( 라) 이내 ...`: 네 hyphen 문장을 각각 줄바꿈한다. 문장 안의 공백 포함 `( 가)`~`( 라)`는 답란이지 제시 항목 제목이 아니므로 거기서 자르지 않는다.
3. `｢신용카드 개인회원 표준 약관｣ ... 주요 내용이다. ( )안에 ... 맞는 것은? ( ) 카드사는 회원의 카드가 ...`: 질문 지시문 뒤에 이어진 긴 보조 본문을 별도 문단으로 표시한다. 목록 기호가 없어도 보조 본문 경계를 인식한다.

사용자 메시지의 원문 3개를 agent brief에 제공한다. 테스트에서는 stem과 options를 올바르게 분리하고, 옵션 `(다), (라)` 또는 `(나) 5년`을 발문 항목으로 옮기지 않는다. 숫자·조건·법률/금융 문구·정답·문자 순서를 바꾸지 않는다. 이 Task는 사실/정답 검증이 아닌 표시/줄바꿈 수정이다.

## 구조와 적용 경로

기존 TS stemItems/StemText/StemItemList와 Python book_core.question.labels/break_stem_items 및 extraction normalizer를 읽고 공통 행동을 맞춘다. 기존 저장 문제도 즉시 올바르게 표시되게 web 렌더 단계에 적용하고, 새 추출은 정규화에서 줄바꿈을 보존한다. 기존 데이터/불변 attempt를 대량 rewrite하지 않는다. fingerprint 공백 정규화·보기 구조·option ID·빈 답 괄호 표시 규칙은 유지한다.

보조 본문을 분리하는 구조는 paragraph/list 단위를 표현하고 라벨 없는 모든 문장에 무차별 개행하지 않는다. 후보 경계는 질문 종료와 별도 제시문 시작, 실제 반복 항목/bullet 경계에 한정한다. `(가)~(라)` 도입 참조, inline 답란, 음수/범위/hyphen 포함 일반 문장, 수식·약어·영문 I/A 목록 혼합, 이미 있는 줄바꿈을 false positive로 분할하지 않는다. idempotent해야 한다. 보수적으로 확정할 수 없는 입력은 원문 순서를 보존한다.
