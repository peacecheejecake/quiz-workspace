# DOC-01 — 문서 관리 (Documents 목록·PDF 업로드)

**상태:** 확정 화면 요구사항 v1.4 · UX1·UX2 개정 2026-10-19 · UX3c 개정 2026-10-20 (문서 관리 floating dialog) · UX6-UPLOAD 개정 2026-10-28 (모든 PDF를 한 곳에서 여러 개 올림, 자동 분류·종류 badge·`종류 변경`)
**Route:** `/workspaces/:workspaceId?panel=documents` (Workspace header `문서 n` 버튼이 여는 non-modal floating dialog "문서 관리"; 이전 `/workspaces/:workspaceId/documents`는 여기로 redirect)
**테스트:** `tests/e2e/documents/documents-library.spec.ts`
**연계:** [전체 아키텍처](../architecture.md), [디자인 시스템](../design-system.md), [E2E 규칙](../e2e-strategy.md)

## 레이아웃 및 컴포넌트
- 상태별 Empty/Loading/Failure/Success UI, 반응형 Layout과 Floating Side Panel, 접근성 지원.
- API와 화면은 owner / viewer / 로그인 상태에 따라 기능과 데이터 표시 범위를 구분한다.
- 모든 편집·상태 변경은 서버 측 인가·revision 일관성을 검증한다.
- **UX3c 2026-10-20:** 문서 관리 dialog에는 페이지 제목·설명이 없다. 위쪽에 공통 `Dropzone`(점선 테두리, 제목 "PDF 파일을 여기에 끌어다 놓으세요", 크기 제한 설명, 키보드·터치용 "PDF 업로드" 버튼) — 편집 권한이 있을 때만. ~~목록에는 책 문서만 있고 문제 PDF(문제지)는 문제 PDF 관리 dialog(QIMPORT-01-AC05)에서 따로 관리하므로 `책`·`문제지` badge는 없다.~~ (UX6-UPLOAD 2026-10-28에서 바뀜: 아래) 각 행: 제목(준비 완료면 DOC-02 링크, 파일 이름은 제목의 tooltip) 오른쪽에 상태 badge(업로드 중·처리 중·준비 완료·실패 …), 다음 줄 메타 `2026. 10. 20. 오전 3:28 · 1.2 MB`("수정" 글자 없음, 가운데 점), 진행률·처리 단계·경과 시간 안내(AC05), 삭제는 휴지통 아이콘 버튼(접근성 이름 "<제목> 삭제", `title` "삭제").
- **모든 PDF 한 곳 업로드 + 자동 분류 (UX6-UPLOAD 2026-10-28, 사용자: "복수의 pdf 같이 올릴 수 있도록 변경 / 문제, 본문 구분 없이 pdf를 올리면 알아서 추출 / 문제 수동 등록은 유지"):** PDF는 종류를 고르지 않고 문서 관리 dialog 한 곳에서 올린다. UX3c의 "책 문서만, badge 없음"을 대체한다.
  - **여러 개 업로드:** Dropzone은 PDF 여러 개를 한 번에 받는다(여러 파일 끌어 놓기, "PDF 업로드" 파일 선택 창의 다중 선택). 파일마다 따로 업로드 의도·업로드·완료를 진행하고 목록에 각자 행과 진행 상태를 가진다. 한 파일의 거부(형식·크기, AC03)나 실패는 다른 파일을 멈추지 않으며 그 파일 이름과 이유를 알린다. 모든 파일은 `document_type = auto`로 올린다(종류 선택 없음).
  - **자동 분류:** 서버(`document.parse` job)가 첫 revision을 게시하기 전에 내용으로 종류를 정한다 — `교재`(본문, `book`), `문제지`(문제만, `question_paper`), `교재+문제`(본문과 문제가 함께 있음, `mixed`; 검색·출제 근거·챕터 매칭에는 교재로 쓰인다). 규칙과 한계는 [questions.md §6](../questions.md). `문제지`와 확신이 높은 `교재+문제`는 서버가 바로 문제 추출을 시작한다(QIMP-AUTO와 같은 run, 문서당 한 번). 확신이 낮은 `교재+문제`와 `교재`는 추출을 시작하지 않는다.
  - **목록과 badge:** 목록은 Workspace의 모든 PDF(교재·문제지·교재+문제)를 보인다. 각 행의 제목 오른쪽, 상태 badge 앞에 종류 badge를 글자로 보인다: `교재` · `문제지` · `교재+문제`. 자동 분류를 기다리는 동안(처리 중이고 종류가 아직 없음, API `kind = null`)은 종류 badge 대신 "분석 중"이며, 분류되지 못하고 실패한 행은 종류 badge가 없다. 종류는 색이 아니라 글자로 전달한다. 문제가 있는 행(종류가 문제지·교재+문제이거나 추출 run이 있음)에는 QIMPORT-01과 같은 규칙으로 `문제 검토` 링크(추출 run이 있으면, `latest_import_id`) 또는 `문제 추출` 버튼(편집 권한, 준비 완료, run 없음)을 보인다. 교재(run 없음)에는 둘 다 없다.
  - **`종류 변경` (AC08):** 편집 권한자에게 준비 완료 행마다 `종류 변경` 메뉴 버튼(접근성 이름 "<제목> 종류 변경", Radix DropdownMenu, 키보드로 열고 고름)이 있다. 항목은 `교재`·`문제지`·`교재+문제`이고 현재 종류가 선택(checked)으로 표시된다. 고르면 바로 `PATCH /documents/{id}`(`kind`)로 저장되고 행·badge·`문서 n`이 갱신된다. 사람이 고른 종류는 서버가 다시 분류하지 않는다(이후 교정 revision 포함). `문제지`·`교재+문제`로 바꾸면 그 PDF에 추출 run이 없을 때 추출을 시작한다(`문제 검토`가 생김). `교재`로 바꿔도 이미 추출된 초안·등록된 문제는 지우지 않는다(`문제 검토`는 남는다). 교재(교재+문제 포함)를 `문제지`로 바꾸면 검색·출제 근거·챕터 매칭에서 빠지므로, 그 PDF의 챕터 아래 등록된 문제나 등록 대기 초안이 있거나 문제의 출처로 인용되면 서버가 거절하고(409 `document-in-use`) 메뉴 아래에 이유 "이 교재의 챕터나 출처를 쓰는 문제가 있어 문제지로 바꿀 수 없습니다."를 alert로 보인다. 처리 중·실패한 행에는 메뉴가 없다(서버도 409 `document-not-ready`). 보기 권한자에게는 메뉴가 없다(서버 403).
  - **`문서 n`:** header의 `문서 n`과 홈의 문서 수는 본문이 있는 PDF(종류 `교재`·`교재+문제`)만 센다. `문제지`와 아직 분류되지 않은("분석 중") PDF는 세지 않는다.

## 수용 기준

### DOC-01-AC01

- **Given:** 해당 화면과 테스트용 데이터 및 권한이 주어진 상태
- **When:** 관련 조작/네트워크 요청을 수행
- **Then:** PDF가 없는 활성 Workspace에서 빈 상태와 업로드 버튼을 제공한다. 업로드 버튼은 dialog 안의 Dropzone 버튼 "PDF 업로드" 하나뿐이며(UX1의 "CTA 하나" 규칙, 2026-10-19), 빈 상태는 "아직 문서가 없습니다" 문구만 보인다. Dropzone은 끌어다 놓기 안내("PDF 파일을 여기에 끌어다 놓으세요")를 점선 영역으로 보이고 파일을 끌어 오는 동안 강조된다(UX2 2026-10-19 → UX3c 2026-10-20 Dropzone으로 대체).

### DOC-01-AC02

- **Given:** 해당 화면과 테스트용 데이터 및 권한이 주어진 상태
- **When:** 관련 조작/네트워크 요청을 수행
- **Then:** 정상 PDF 업로드를 완료하면 parser/index 작업 진행률과 READY 상태가 표시된다.

### DOC-01-AC03

- **Given:** 해당 화면과 테스트용 데이터 및 권한이 주어진 상태
- **When:** 관련 조작/네트워크 요청을 수행
- **Then:** 미지원 형식 및 허용 크기 초과는 프론트와 서버 모두에서 거부하고 사유를 제공한다.

### DOC-01-AC04

- **Given:** 해당 화면과 테스트용 데이터 및 권한이 주어진 상태
- **When:** 관련 조작/네트워크 요청을 수행
- **Then:** 네트워크 중단 시 재개 가능한 업로드를 지원하며 재시도로 중복 문서를 생성하지 않는다.

### DOC-01-AC05

- **Given:** 처리 중인 문서가 있고, 이 탭이 그 작업을 실시간으로 따라가지 않는 상태(새로고침·다른 탭에서 업로드 등)
- **When:** 문서 목록을 열거나 목록이 갱신(폴링)됨
- **Then:** 목록 API(`GET /workspaces/{id}/documents`, 문서 상세도 동일)는 문서마다 대기·실행 중인 처리 작업(`processing_job`: 상태, 단계, 진행률, 대기 시작·실행 시작 시각)을 함께 반환하고, 행은 그 상태를 텍스트로 표시한다: 대기 중이면 "처리 대기 중", worker가 parser 모델을 불러오는 동안(`preparing` 단계, 콜드 스타트)은 "처리 준비 중", 그 뒤로는 기존 단계 표시("처리 중 · 파싱 중" 등). 작업이 30초를 넘게 대기·실행 중이면 경과 시간("1분 5초째 처리 중")과 안내 "첫 처리나 큰 PDF는 몇 분 걸릴 수 있습니다."를 함께 표시한다. 상태는 색이 아니라 텍스트로 전달하며, 작업 정보는 요청자가 접근할 수 있는 Workspace 안에서만 조회한다(UX3-JOB 2026-10-20).

### DOC-01-AC06

- **Given:** 교재 문서, 문제지, 교재+문제 PDF가 함께 등록된 Workspace 홈
- **When:** header의 `문서 n` 버튼을 누름
- **Then:** "문서 관리" non-modal floating dialog가 열리고(`?panel=documents`) 목록은 세 PDF를 모두 보이며 각 행에 종류 badge(`교재`/`문제지`/`교재+문제`, 글자)가 있다. n은 본문이 있는 PDF(교재와 교재+문제, 여기서는 2)만 센다(UX6-UPLOAD 2026-10-28; 이전 UX3c는 책 문서만 나열하고 badge 없음). 페이지 제목·설명은 없고, 편집 권한이 있으면 점선 Dropzone이 보인다. 상태 badge(예: "준비 완료")는 종류 badge 오른쪽, 메타 줄은 `<날짜 시각> · <용량>`("수정" 글자·파일 이름 없음), 파일 이름은 제목의 tooltip으로만 보인다. 삭제는 휴지통 아이콘 버튼(접근성 이름 "<제목> 삭제")이고 확인 후 목록이 줄어들며, 지운 PDF가 교재(또는 교재+문제)면 `문서 n`도 함께 줄어든다(UX3c).

### DOC-01-AC07

- **Given:** 편집 권한자가 연 문서 관리 dialog (`문서 n` = 0)
- **When:** 합성 교재 PDF(`book-ko.pdf`)와 합성 문제 PDF(`questions-ko.pdf`)를 한 번에 Dropzone에 끌어 놓는다(또는 "PDF 업로드"에서 둘을 함께 고른다). 종류는 고르지 않는다.
- **Then:** 두 파일이 각자의 행과 진행 상태로 업로드·처리되고(종류가 정해지기 전에는 "분석 중"), 처리가 끝나면 `book-ko`는 `교재`, `questions-ko`는 `문제지` badge를 보인다. `문제지` 행은 사용자가 아무것도 누르지 않아도 서버가 추출을 시작해 `문제 검토` 링크가 생기고, 그 링크의 가져오기 페이지(`?document=<id>`)에 추출된 초안이 보인다. `교재` 행에는 추출이 시작되지 않아 `문제 검토` 링크가 없다. `문서 n`은 1(교재만)이다. 같은 업로드를 다시 시도해도 문서·추출 run이 중복 생성되지 않는다(AC04, QIMPORT-01-AC06).

### DOC-01-AC08

- **Given:** 편집 권한자와 보기 권한자가 있는 Workspace에 자동 분류된 준비 완료 PDF 두 개: `문제지`(추출 run 있음)와 `교재`(그 챕터 아래 등록된 문제가 있음)
- **When:** 편집 권한자가 문서 관리에서 `문제지` 행의 `<제목> 종류 변경` 메뉴를 키보드로 열어 `교재+문제`를 고르고, 이어서 `교재` 행의 메뉴에서 `문제지`를 고른다. 보기 권한자로 같은 dialog를 연다.
- **Then:** 첫 PDF의 badge가 `교재+문제`로 바뀌고 `문서 n`이 1 늘며, 기존 추출 run과 `문제 검토` 링크는 그대로다(초안을 지우거나 run을 새로 만들지 않음). 다시 불러와도 종류는 사람이 고른 `교재+문제`로 유지된다(서버가 재분류하지 않음). 두 번째 PDF는 쓰이고 있어 바뀌지 않고 이유("이 교재의 챕터나 출처를 쓰는 문제가 있어 문제지로 바꿀 수 없습니다.")가 alert로 보이며 badge는 `교재`로 남는다. 보기 권한자에게는 `종류 변경` 메뉴가 없다.
