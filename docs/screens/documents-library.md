# DOC-01 — 문서 관리 (Documents 목록·PDF 업로드)

**상태:** 확정 화면 요구사항 v1.3 · UX1·UX2 개정 2026-10-19 · UX3c 개정 2026-10-20 (문서 관리 floating dialog) · UX6-PROGRESS 개정 2026-10-28 (단계 진행 표시)
**Route:** `/workspaces/:workspaceId?panel=documents` (Workspace header `문서 n` 버튼이 여는 non-modal floating dialog "문서 관리"; 이전 `/workspaces/:workspaceId/documents`는 여기로 redirect)
**테스트:** `tests/e2e/documents/documents-library.spec.ts`
**연계:** [전체 아키텍처](../architecture.md), [디자인 시스템](../design-system.md), [E2E 규칙](../e2e-strategy.md)

## 레이아웃 및 컴포넌트
- 상태별 Empty/Loading/Failure/Success UI, 반응형 Layout과 Floating Side Panel, 접근성 지원.
- API와 화면은 owner / viewer / 로그인 상태에 따라 기능과 데이터 표시 범위를 구분한다.
- 모든 편집·상태 변경은 서버 측 인가·revision 일관성을 검증한다.
- **UX3c 2026-10-20:** 문서 관리 dialog에는 페이지 제목·설명이 없다. 위쪽에 공통 `Dropzone`(점선 테두리, 제목 "PDF 파일을 여기에 끌어다 놓으세요", 크기 제한 설명, 키보드·터치용 "PDF 업로드" 버튼) — 편집 권한이 있을 때만. 목록에는 책 문서만 있고 문제 PDF(문제지)는 문제 PDF 관리 dialog(QIMPORT-01-AC05)에서 따로 관리하므로 `책`·`문제지` badge는 없다. 각 행: 제목(준비 완료면 DOC-02 링크, 파일 이름은 제목의 tooltip) 오른쪽에 상태 badge(업로드 중·처리 중·준비 완료·실패 …), 다음 줄 메타 `2026. 10. 20. 오전 3:28 · 1.2 MB`("수정" 글자 없음, 가운데 점), 진행률·처리 단계·경과 시간 안내(AC05), 삭제는 휴지통 아이콘 버튼(접근성 이름 "<제목> 삭제", `title` "삭제").
- **단계 진행 표시 (UX6-PROGRESS 2026-10-28, 사용자 피드백 "진행률 막대가 여러 단계를 거치며 다 찼다가 줄어들었다 하는데, 각 단계의 경과를 명확히 볼 수 있도록 step UI"):** 업로드·처리 중인 행은 공통 `StepProgress`(design-system §7)로 `업로드 → 분석 → 색인` 세 단계를 보인다. 각 단계는 완료(체크 아이콘)·진행 중(번호, 굵게)·대기(번호)로 표시되고 스크린 리더에는 "완료"/"진행 중"/"대기"를 읽는다(색만으로 구분하지 않음). 진행 막대는 단계 수만큼 나뉜 하나의 막대로, 완료 단계 칸은 가득, 현재 단계 칸은 그 단계의 진행률만큼 차므로 단계가 바뀌어도 줄어들지 않는다. 단계 대응: `업로드` = 파일 확인·업로드 준비·업로드(보낸 바이트 %)·업로드 확인, `분석` = 처리 대기·처리 준비(`preparing`)·파일 읽기·파싱·구조 분석(작업 진행률 0–50%를 이 칸의 0–100%로), `색인` = 분할·색인·게시(작업 진행률 50–100%). 이 탭이 업로드하지 않은 처리 중 문서(AC05)도 `업로드`를 완료로 보인다. 진행률 이름은 업로드 단계에서 "업로드 진행률", 그 뒤 "파싱·색인 진행률"이고 값 텍스트는 "2/3단계: 분석 중, 30%" 형식이다. 막대는 값 사이를 부드럽게 잇고 `prefers-reduced-motion`에서는 바로 바뀐다.

## 수용 기준

### DOC-01-AC01

- **Given:** 해당 화면과 테스트용 데이터 및 권한이 주어진 상태
- **When:** 관련 조작/네트워크 요청을 수행
- **Then:** PDF가 없는 활성 Workspace에서 빈 상태와 업로드 버튼을 제공한다. 업로드 버튼은 dialog 안의 Dropzone 버튼 "PDF 업로드" 하나뿐이며(UX1의 "CTA 하나" 규칙, 2026-10-19), 빈 상태는 "아직 문서가 없습니다" 문구만 보인다. Dropzone은 끌어다 놓기 안내("PDF 파일을 여기에 끌어다 놓으세요")를 점선 영역으로 보이고 파일을 끌어 오는 동안 강조된다(UX2 2026-10-19 → UX3c 2026-10-20 Dropzone으로 대체).

### DOC-01-AC02

- **Given:** 해당 화면과 테스트용 데이터 및 권한이 주어진 상태
- **When:** 관련 조작/네트워크 요청을 수행
- **Then:** 정상 PDF 업로드를 완료하면 parser/index 작업 진행률과 READY 상태가 표시된다. 업로드 중에는 단계 표시가 `업로드` 진행 중, `분석`·`색인` 대기로 보인다(UX6-PROGRESS).

### DOC-01-AC03

- **Given:** 해당 화면과 테스트용 데이터 및 권한이 주어진 상태
- **When:** 관련 조작/네트워크 요청을 수행
- **Then:** 미지원 형식 및 허용 크기 초과는 프론트와 서버 모두에서 거부하고 사유를 제공한다.

### DOC-01-AC04

- **Given:** 해당 화면과 테스트용 데이터 및 권한이 주어진 상태
- **When:** 관련 조작/네트워크 요청을 수행
- **Then:** 네트워크 중단 시 재개 가능한 업로드를 지원하며 재시도로 중복 문서를 생성하지 않는다.

### DOC-01-AC05

- **Given:** 처리 중인 문서가 있고, 이 탭이 그 작업을 실시간으로 따라가지 않는 상태(새로고침·다른 탭에서 업로드 등)
- **When:** 문서 목록을 열거나 목록이 갱신(폴링)됨
- **Then:** 목록 API(`GET /workspaces/{id}/documents`, 문서 상세도 동일)는 문서마다 대기·실행 중인 처리 작업(`processing_job`: 상태, 단계, 진행률, 대기 시작·실행 시작 시각)을 함께 반환하고, 행은 그 상태를 텍스트로 표시한다: 대기 중이면 "처리 대기 중", worker가 parser 모델을 불러오는 동안(`preparing` 단계, 콜드 스타트)은 "처리 준비 중", 그 뒤로는 기존 단계 표시("처리 중 · 파싱 중" 등). 작업이 30초를 넘게 대기·실행 중이면 경과 시간("1분 5초째 처리 중")과 안내 "첫 처리나 큰 PDF는 몇 분 걸릴 수 있습니다."를 함께 표시한다. 단계 표시는 `업로드` 완료, `분석` 진행 중(`preparing`), `색인` 대기다(UX6-PROGRESS). 상태는 색이 아니라 텍스트로 전달하며, 작업 정보는 요청자가 접근할 수 있는 Workspace 안에서만 조회한다(UX3-JOB 2026-10-20).

### DOC-01-AC06

- **Given:** 책 문서와 문제 PDF(문제지)가 함께 등록된 Workspace 홈
- **When:** header의 `문서 n` 버튼을 누름
- **Then:** "문서 관리" non-modal floating dialog가 열리고(`?panel=documents`) n과 목록은 책 문서만 센다(문제 PDF는 문제 PDF 관리 dialog에만 있다). 페이지 제목·설명은 없고, 편집 권한이 있으면 점선 Dropzone이 보인다. 행에는 `책`/`문제지` badge가 없으며 상태 badge(예: "준비 완료")는 제목 바로 오른쪽, 메타 줄은 `<날짜 시각> · <용량>`("수정" 글자·파일 이름 없음), 파일 이름은 제목의 tooltip으로만 보인다. 삭제는 휴지통 아이콘 버튼(접근성 이름 "<제목> 삭제")이고 확인 후 목록과 `문서 n`이 함께 줄어든다(UX3c).
