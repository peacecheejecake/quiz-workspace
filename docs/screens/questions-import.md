# QIMPORT-01 — 문제 PDF 가져오기

**상태:** 확정 화면 요구사항 v1.4 · UX3c 개정 2026-10-20 (문제 PDF 관리 dialog) · UX4 개정 2026-10-21 (`문제` 메뉴 진입, `PDF 가져오기` 버튼 삭제) · QIMP-AUTO 개정 2026-10-21 (서버 측 추출 시작, `문제 추출`/`문제 검토`) · QIMP-BULK 개정 2026-10-22 (선택 후 일괄 승인·등록) · QIMP-JOB 개정 2026-10-23 (서버 측 등록) · CHAPTER-MAP 개정 2026-10-23 (교재 챕터 자동 매칭·수정) · UX6-PROGRESS 개정 2026-10-28 (단계 진행 표시)
**Route:** `/workspaces/:workspaceId/questions/import` (업로드·추출·검토 페이지; 뒤로가기·breadcrumb `Workspace 이름 › 문제 PDF 가져오기`; `?document=<문서 id>`이면 그 문제 PDF의 가장 최근 추출을, 없으면 Workspace의 가장 최근 추출을 보인다) · 문제 PDF 관리 dialog `/workspaces/:workspaceId?panel=question-pdfs`
**테스트:** `tests/e2e/questions/questions-import.spec.ts`
**연계:** [전체 아키텍처](../architecture.md), [디자인 시스템](../design-system.md), [E2E 규칙](../e2e-strategy.md)

## 레이아웃 및 컴포넌트
- 상태별 Empty/Loading/Failure/Success UI, 반응형 Layout과 Floating Side Panel, 접근성 지원.
- API와 화면은 owner / viewer / 로그인 상태에 따라 기능과 데이터 표시 범위를 구분한다.
- 모든 편집·상태 변경은 서버 측 인가·revision 일관성을 검증한다.
- **문제 PDF 관리 dialog (UX3c 2026-10-20):** 문제 PDF(`document_type = question_paper`)는 책 문서와 다른 목록에서 관리한다. Workspace 홈 header의 `문제` 메뉴 › `PDF 관리`(UX4 2026-10-21; 이전 문제 영역의 `문제 PDF 관리` 버튼)와 문제은행의 `PDF 가져오기`(QBANK-01-AC06)가 같은 non-modal floating dialog "문제 PDF 관리"를 연다: 등록된 문제 PDF 목록(문서 관리와 같은 행 형식, badge 없음)과 점선 Dropzone(놓거나 "PDF 선택" 버튼으로 고른 PDF를 들고 이 페이지로 이동해 바로 업로드·추출을 시작). dialog 안의 별도 `PDF 가져오기` 버튼은 없다(UX4) — Dropzone의 "PDF 선택"이 키보드·터치 경로다. 목록이 비면 "등록된 문제 pdf가 없습니다." 문구. 추출 결과 검토(초안 편집·원본 비교·선택 승인·등록)는 dialog에 담기에 넓어 이 페이지에 남긴다. 홈의 다른 "PDF 가져오기" 버튼(빈 상태 등)은 없다.

- **서버 측 추출 시작 (QIMP-AUTO 2026-10-21):** 문제 추출은 브라우저가 아니라 서버가 시작한다. 문제 PDF의 처리(파싱·색인, `document.parse`)가 성공하면 같은 트랜잭션에서 그 문서의 import run과 `question.import` job이 업로드한 사용자 이름으로, 문서의 Workspace에 한 번만 만들어진다(문서당 서버 시작 run 1개; 재시도·중복 전달·이후 revision은 새 run을 만들지 않는다; 보관·삭제된 Workspace, 편집 권한을 잃은 사용자, 이미 run이 있는 문서는 시작하지 않는다). 따라서 업로드가 끝나면 페이지를 떠나도 되며, 진행 표시 아래에 "이 페이지를 떠나도 PDF 분석과 문제 추출은 서버에서 계속됩니다. 다시 열면 결과를 이어서 볼 수 있습니다."를 보인다(업로드 단계 제외). 페이지에 남아 있으면 처리 완료 후 `POST /question-imports`가 그 run에 붙어(attach) 진행과 결과를 보인다 — 같은 문서의 활성 revision에 run이 이미 있으면 POST는 새 run을 만들지 않고 그 run을 돌려준다.
- **선택 후 일괄 승인·등록 (QIMP-BULK 2026-10-22):** 실제 문제 PDF는 초안이 수백 개(316쪽 → 750개)라 초안마다 승인 요청을 보내지 않는다. 초안마다 `선택` 체크박스가 있고(이름 `N번 문제 선택`), 체크는 화면 상태일 뿐 서버에 아무것도 보내지 않는다. 초안 목록 위의 `전체 선택 (n개)` 체크박스는 확인할 것이 없는 선택 가능 초안 — 아직 등록되지 않았고, 승인 불가 항목(error 검증, 정답 없는 객관식 등)이 없고, 정답이 있고(주관식·서술형은 정답 없이도 확정할 수 있지만 일괄 선택하지 않는다), 확인 항목(warning 검증, 예: 정답지 매칭 실패)이 없고, 제외(rejected)되지 않은 초안 — 을 모두 선택/해제하며, 일부만 선택되면 중간 상태(indeterminate)다. n은 그 범위의 개수다. 승인 불가 초안의 체크박스는 비활성이고 이유(예: "정답 보기를 지정해야 승인할 수 있습니다")를 설명으로 보인다 — 편집으로 고치면 선택할 수 있다. 정답이 없거나 확인 항목이 있거나 제외된 초안은 전체 선택에 들지 않지만 개별로 선택할 수 있다(조용히 일괄 등록되지 않는다). `선택한 문제 승인 및 등록 (k)` 버튼(k = 선택 수)이 선택한 초안을 화면에 보이는 version 그대로 승인하고 문제은행에 등록한다(서버 측 등록, 아래 QIMP-JOB): 승인(reviewer = 누른 사용자, 승인 시각 기록)과 등록은 초안별로 멱등이다(재시도·중복 전달은 중복 등록하지 않음). 서버가 거절한 초안(선택 후 다른 사람이 바꿈 `stale-draft`, 확정할 수 없음 `not-publishable`)은 승인도 등록도 되지 않고 선택된 채 남으며, 화면은 등록한 수와 거절된 초안 번호·이유를 알리고 초안 목록을 다시 불러온다. 등록된 초안은 선택에서 빠지고 체크박스 대신 `등록됨` 상태만 보인다. 편집은 그대로이며, 선택된 초안을 편집하면 저장된 최신 version으로 등록된다(편집으로 승인 불가가 되면 선택할 수 없고 등록 대상에서 빠진다).
- **서버 측 등록 (QIMP-JOB 2026-10-23):** "문제 등록하고 화면을 끄거나 페이지를 벗어나도 서버에서 선택한 모든 문제가 등록처리되어야 함"(사용자). `선택한 문제 승인 및 등록`은 선택 전체를 한 번에 `POST /question-imports/{id}/registrations`(`{draft_id, version}` 목록, 최대 5000개, `Idempotency-Key`)로 보낸다. 서버는 선택을 기록하고(초안·보낸 version; 이미 등록된 초안은 `건너뜀`, 바뀐 초안·확정할 수 없는 초안은 그 자리에서 거절) `question.import_register` job이 batch마다 한 트랜잭션에서 승인과 등록을 이어 간다 — 페이지를 떠나거나 브라우저를 닫아도 계속되며, worker가 중간에 죽어도 재시도가 남은 초안만 이어서 처리한다(중복 등록 없음). job은 누른 사용자 이름으로 그 run의 Workspace에서 돌고, batch마다 Workspace가 활성이고 사용자가 편집 권한을 가졌는지 다시 확인한다(보관·삭제·권한 상실 → 남은 초안은 등록하지 않고 job 실패 `workspace_unavailable`, 화면은 "보관된 Workspace…" 이유를 보인다). 이전 등록이 아직 대기·진행 중이면 새 등록은 409(`import-registration-running`)이고 화면은 진행 중인 등록에 붙는다. 진행 중에는 `등록 진행률` 진행 막대(공용 `ProgressBar`)와 `승인·등록 중 · k개 중 n개 처리`, 그리고 "이 페이지를 떠나도 선택한 문제의 승인·등록은 서버에서 계속됩니다."를 보인다. 페이지를 다시 열면(run의 `registration_job_id`) 진행 중인 등록에 다시 붙어 진행을 보이고, 끝나면 초안 목록을 다시 불러와 등록 결과(등록 수, 거절 번호·이유)를 알린다. 서버가 초안을 읽은 뒤(페이지가 오는 사이) 끝난 등록도 같은 방식으로 목록을 다시 불러오고 결과를 알린다. 등록 중에는 선택·전체 선택·등록 버튼이 비활성이다(편집은 가능 — 편집된 초안은 version이 바뀌어 `stale-draft`로 거절된다).
- **교재 챕터 자동 매칭 + 수정 (CHAPTER-MAP 2026-10-23, 사용자 결정 "교재 챕터에 자동 매칭 + 수정 가능"):** 가져온 문제는 교재(`document_type = book`) 챕터 아래에 등록된다. 초안마다 서버가 챕터를 추천한다: 문제 PDF에서 그 문제의 첫 출처 블록이 속한 장(그리고 그 상위 장)의 제목을 Workspace 책들의 현재 revision 챕터 제목과 정규화해 비교한다(NFKC·대소문자 무시, 앞의 `제N장`/`N장`/`Chapter N`/`N.`/`N.M` 번호와 공백·문장부호 제거 — "제1장 수신제도" = "1장 수신 제도"). 가장 깊은 장부터 보며 같은 제목의 교재 챕터가 정확히 하나면 그 챕터, 여럿이면 장 번호가 같은 하나로 좁히고, 그래도 여럿이면 추천하지 않는다(`ambiguous`). 없으면(`no_match`), 문제 PDF에 장이 없으면(`no_source_chapter`) 챕터 없음. 추천은 읽을 때마다 현재 교재로 다시 계산한다(나중에 올린 교재도 반영). 각 초안에 `N번 문제 챕터` 선택 상자(교재 챕터 목록 + "챕터 없음", 책이 여럿이면 책 이름 표시)와 이유 문구("문제 PDF의 ‘…’에 맞춰 자동으로 골랐습니다." / "… 같은 교재 챕터가 없어 챕터 없이 등록됩니다." / "… 이름이 같은 교재 챕터가 여러 개라 자동으로 고르지 않았습니다." / "직접 고른 챕터로 등록합니다.")를 보인다. 고르면 바로 저장(`PATCH /question-drafts/{id}` `chapter_id`, 편집 권한; 내용이 아니므로 승인 상태 유지, version은 바뀜)되고 이후 추천이 덮지 않는다. 등록(서버 등록 job과 publish)은 화면에 보이는 챕터를 쓴다: 선택과 함께 초안마다 보이던 챕터(`chapter_id`, 없음 = null)를 보내고, 그 사이 추천이 바뀌었으면(예: 교재가 추가됨 — 초안 version은 그대로) 요청 전체를 409 `chapter-changed`로 거절해 다른 챕터로 조용히 등록하지 않는다(화면은 이유를 알리고 초안 목록을 다시 불러오며 선택은 유지). 제출 뒤 등록 job이 돌기 전에 교재가 교정 게시되면 같은 섹션의 새 revision 챕터로 등록된다(없으면 챕터 없음). 보기 권한·등록된 초안은 챕터를 글로만 보인다. 등록된 문제의 챕터는 문제은행 편집기의 `챕터`에서 바꾼다(기존 기능).
- **단계 진행 표시 (UX6-PROGRESS 2026-10-28):** 업로드부터 추출까지의 진행은 공통 `StepProgress`(design-system §7)로 `업로드 → PDF 분석 → 문제 추출` 세 단계를 보인다(이전에는 한 막대가 단계마다 0→100%로 찼다가 줄어들었다). 각 단계는 완료(체크 아이콘)·진행 중(번호, 굵게)·대기(번호)이고 스크린 리더에는 "완료"/"진행 중"/"대기"로 읽힌다. 막대(이름 "가져오기 진행률")는 세 칸으로 나뉘어 완료 칸은 가득, 현재 칸은 그 단계의 진행률(업로드 바이트 %, PDF 처리 작업 %, 추출 작업 %)만큼 차므로 줄어들지 않는다. 값 텍스트는 "2/3단계: PDF 분석 중, 30%" 형식. 단계 위 문구("PDF 분석 중 · 파일 이름 · 30%")와 서버 계속 안내는 그대로다. 등록 진행률(QIMP-JOB)은 한 단계 작업이라 보통 `ProgressBar`다.
- **문제 PDF 관리의 행 동작 (QIMP-AUTO):** 준비 완료된 문제 PDF 행은 추출 run이 있으면(문서 목록 API가 문제 PDF마다 돌려주는 `latest_import_id`로 판단 — Workspace의 run 목록 일부로 추정하지 않는다) `문제 검토` 링크(모든 구성원, `?document=<id>` 가져오기 페이지로 이동), 없으면(QIMP-AUTO 이전에 처리된 PDF) 편집 권한자에게 `문제 추출` 버튼을 보인다. `문제 추출`은 추출을 시작(POST)하고 그 문서의 가져오기 페이지로 이동해 진행·검토를 보인다. 처리 중이거나 실패한 행에는 둘 다 없다. 시작에 실패하면 dialog 안에 이유를 alert로 보인다.

## 수용 기준

### QIMPORT-01-AC01

- **Given:** 해당 화면과 테스트용 데이터 및 권한이 주어진 상태
- **When:** 관련 조작/네트워크 요청을 수행
- **Then:** 문제 5개 포함 PDF 업로드/추출 시 원본 PDF 페이지를 연결한 draft 5개를 표시한다. 업로드·추출 중에는 `업로드 → PDF 분석 → 문제 추출` 단계 표시가 지금 단계를 진행 중, 지난 단계를 완료, 남은 단계를 대기로 보인다(UX6-PROGRESS).

### QIMPORT-01-AC02

- **Given:** 해당 화면과 테스트용 데이터 및 권한이 주어진 상태
- **When:** 관련 조작/네트워크 요청을 수행
- **Then:** 정답 없는 PDF의 추출 결과는 정답 null로 저장하며 모델이 임의로 정답을 생성하지 않는다.

### QIMPORT-01-AC03

- **Given:** 해당 화면과 테스트용 데이터 및 권한이 주어진 상태
- **When:** 관련 조작/네트워크 요청을 수행
- **Then:** 사용자가 검토해 선택한 초안만 승인과 함께 문제은행에 확정 등록하고(선택 체크 자체는 서버에 보내지 않고 `선택한 문제 승인 및 등록`에서 한 번에 처리; `전체 선택 (n개)`은 등록되지 않았고 정답이 있으며 확인 항목이 없는 초안 전체를 고르고 일부 선택이면 중간 상태) Heatmap 마커를 증가시킨다. 선택하지 않은 초안과 승인 불가 초안(정답 없는 객관식 등)은 등록되지 않는다(QIMP-BULK).

### QIMPORT-01-AC04

- **Given:** 해당 화면과 테스트용 데이터 및 권한이 주어진 상태
- **When:** 관련 조작/네트워크 요청을 수행
- **Then:** 작업 실패 후 재시도 시 초안·확정 문제를 중복 등록하지 않는다.

### QIMPORT-01-AC05

- **Given:** 문제 PDF와 책 문서가 등록된 Workspace 홈(그리고 문제 PDF가 없는 Workspace)
- **When:** header의 `문제` 메뉴에서 `PDF 관리`를 고름(UX4)
- **Then:** "문제 PDF 관리" floating dialog가 열려(`?panel=question-pdfs`) 문제 PDF만 나열하고(책 문서는 없음), Dropzone과 그 "PDF 선택" 버튼을 보인다(편집 권한). dialog에도 홈에도 별도의 "PDF 가져오기" 버튼은 없다(UX4). 문제 PDF가 없으면 "등록된 문제 pdf가 없습니다."를 보인다. Dropzone에 PDF를 놓거나 "PDF 선택"으로 고르면 가져오기 페이지로 이동해 그 파일의 업로드를 바로 시작한다(UX3c).

### QIMPORT-01-AC06

- **Given:** 편집 권한자가 문제 PDF를 올린 Workspace (그리고 추출 run 없이 처리만 끝난 문제 PDF)
- **When:** 업로드가 끝난 뒤 처리 완료 전에 가져오기 페이지를 떠났다가 나중에 다시 연다 (그리고 문제 PDF 관리 dialog에서 그 PDF의 `문제 추출`을 누른다)
- **Then:** 처리가 끝나면 서버가 브라우저 없이 추출을 시작해(업로드한 사용자의 run 1개) 다시 연 가져오기 페이지에 추출된 초안이 보인다. 추출 run이 없는 처리 완료 문제 PDF는 `문제 추출`을 제공하고, 누르면 추출을 시작해 그 문서의 가져오기 페이지(`?document=`)에서 초안을 보이며, 이후 그 행은 `문제 검토` 링크를 보인다. 어떤 경우에도 한 문서에 run이 중복 생성되지 않는다(QIMP-AUTO).

### QIMPORT-01-AC07

- **Given:** 편집 권한자가 추출된 초안 여러 개를 선택한 가져오기 페이지(서버 등록 batch보다 많은 선택)
- **When:** `선택한 문제 승인 및 등록`을 누르고 등록이 끝나기 전에 페이지를 떠났다가(다른 페이지로 이동하거나 창을 닫음) 나중에 다시 연다
- **Then:** 브라우저 없이도 서버가 선택한 모든 초안을 승인·등록해 문제은행에 확정 문제가 정확히 그 수만큼 생긴다(중복 없음, 확정할 수 없는 초안·선택 후 바뀐 초안은 등록하지 않고 이유를 남김). 다시 연 페이지는 진행 중이면 `등록 진행률`을 보이며 따라가고, 끝나면 모든 선택 초안을 `등록됨`으로 보인다(QIMP-JOB).

### QIMPORT-01-AC08

- **Given:** 교재(책)가 등록된 Workspace에서 문제 PDF를 가져와 초안이 있는 가져오기 페이지 (문제 PDF의 장 제목과 같은 제목의 교재 챕터가 하나 있음)
- **When:** 초안의 챕터를 확인하고 한 초안의 챕터를 다른 교재 챕터로 바꾼 뒤 그 초안들을 승인·등록한다
- **Then:** 각 초안은 문제 PDF의 장과 제목이 일치하는 교재 챕터를 자동 추천으로 보이고(일치가 없거나 여럿이면 챕터 없음과 이유), 바꾼 챕터는 바로 저장되어 유지되며, 등록된 문제는 문제은행에서 각자 화면에 보이던 챕터 아래에 나온다(CHAPTER-MAP).
