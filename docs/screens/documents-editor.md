# DOC-02 — PDF 열람·원문 교정

**상태:** 확정 화면 요구사항 v1.4 (DOCVIEW 보기 개선 2026-11-01)
**Route:** `/workspaces/:workspaceId/documents/:documentId`
**테스트:** `tests/e2e/documents/documents-editor.spec.ts`
**연계:** [전체 아키텍처](../architecture.md), [디자인 시스템](../design-system.md), [E2E 규칙](../e2e-strategy.md)

## 레이아웃 및 컴포넌트
- 왼쪽 floating 목차 panel(접기·펼치기)·PDF.js 뷰어(연속 스크롤)·폭 조정 구분선·쪽별로 묶은 canonical text 블록 편집기(DOCVIEW 이전: 좌측 목차·중앙 뷰어·우측 편집기 3단). Draft/Published revision 분리, error recovery 지원.
- API와 화면은 owner / viewer / 로그인 상태에 따라 기능과 데이터 표시 범위를 구분한다.
- 모든 편집·상태 변경은 서버 측 인가·revision 일관성을 검증한다.
- **텍스트 내보내기·요약 (DOCSUM-SPEC 2026-10-29):** header에 `텍스트 내보내기` 메뉴(Markdown·텍스트·전체 복사, 편집 권한자는 교정 중 초안도; [DOC-03](documents-text-export.md))와, 교재 문서면 `요약` 링크(Workspace 홈의 요약 panel `?panel=document-summary&document=<id>`로 이동; [DOCSUM-01](documents-summary.md))가 있다. 요약을 한 번 만든 문서는 여기서 교정본을 발행할 때마다 요약이 자동으로 다시 만들어진다(DOCSUM-01-AC02). 이 화면의 기존 AC는 바뀌지 않는다.

### 보기 개선 (DOCVIEW, 사용자 피드백 2026-11-01)

사용자 요청: "좌측 목차를 floating dialog 위로, 접었다 펼칠 수 있게", "PDF 페이지 넘길 때마다 왜 이렇게 오래 걸리는지? PDF 로딩 구조 개선", "PDF 페이지를 넘기거나 스크롤하면 인식된 텍스트 영역도 해당 영역이 보이도록", "텍스트 영역을 쪽별로 모아서 보여주기", "PDF 영역과 텍스트 영역의 width를 드래그로 조정할 수 있도록", "텍스트 영역에서 문제로 인식된 것은 문제 형식으로 보여주기". 공유 화면(WS-VIEW-01)의 문서 보기도 같은 viewer 부품을 쓰므로 같은 동작을 한다(편집 UI 없음).

- **목차 panel (AC06):** 목차는 화면 왼쪽에 뜨는 non-modal floating panel(`FloatingSidePanel`, `side="start"`, 제목 `목차`)이다. PDF 도구 막대의 `목차` 토글 버튼(`aria-expanded`)과 panel의 닫기 버튼·Escape(panel 안에 focus가 있을 때)로 접고 펼친다. 접으면 PDF와 원문 텍스트가 화면 폭 전체를 쓴다. 데스크톱(≥1024px)에서는 처음에 펼쳐져 있고 panel이 열린 동안 본문이 panel 폭만큼 비켜서 PDF를 가리지 않는다. 더 좁은 화면에서는 처음에 접혀 있고 펼치면 불투명 panel(모바일은 bottom sheet)로 덮으며, 항목을 고르면 panel이 닫힌다. 펼침/접힘은 이 브라우저에 기억한다(`localStorage`, 없거나 막혀 있으면 기본값). 페이지를 열 때 저장된 상태로 펼쳐지는 panel은 focus를 가져가지 않는다.
- **PDF 로딩 구조 (AC07):** 원본은 화면을 열 때 한 번만 내려받아(서명 URL 한 번, 전체 200 GET) PDF.js 문서 하나로 연다. 쪽은 위아래로 이어진 연속 스크롤로 보이며, 모든 쪽은 첫 쪽 크기의 자리(placeholder)를 갖고 화면에 보이는 쪽과 그 앞뒤 이웃 쪽만 canvas로 그린다(보이는 쪽이 먼저, 한 번에 하나). 멀리 벗어난 쪽의 canvas는 해제해 메모리를 지키고, 최근에 그린 쪽은 다시 그리지 않는다. 쪽을 넘기거나 스크롤해도 서버 요청(원본·서명 URL·원문 API·RSC)이 없다. 원문 텍스트 영역은 쪽이 바뀌어도 바뀐 쪽 묶음만 다시 그린다(블록 수에 비례한 재렌더 없음). `현재 페이지` 칸·`이전/다음 페이지`·확대/축소/폭 맞춤은 그대로이며, 쪽 이동은 해당 쪽으로 즉시(애니메이션 없이) 스크롤한다.
- **PDF ↔ 텍스트 동기화 (AC08):** 현재 쪽은 PDF 영역 위쪽 1/4 선에 걸친 쪽이다. 사용자가 PDF를 스크롤하거나 쪽을 넘기면 `현재 페이지`가 바뀌고, 원문 텍스트 영역이 그 쪽 묶음의 제목이 보이도록 스크롤한다(그 쪽에서 시작하는 블록이 없으면 그 쪽으로 이어지는 블록, 그것도 없으면 앞쪽의 가장 가까운 묶음). 블록을 편집하는 중에는 텍스트 영역을 움직이지 않는다. 텍스트 영역에서 블록을 고르거나(`위치`) 목차에서 장·절을 고르면 이전처럼 PDF가 그 쪽·위치로 이동하고 텍스트는 고른 블록에 머문다.
- **쪽별 묶음 (AC09):** 원문 텍스트는 블록의 첫 쪽으로 묶어 `N쪽` 제목(h3)을 단 묶음(`role="group"`, 이름 `N쪽`)으로 보인다. 현재 쪽 묶음 제목에 `aria-current="page"`. 블록 메타의 쪽 표시는 묶음 제목으로 옮겨 지우고, 여러 쪽에 걸친 블록만 `N–M쪽`을 남긴다.
- **폭 조정 (AC10):** 태블릿 이상(≥768px)에서 PDF 영역과 원문 텍스트 영역 사이에 세로 구분선(`role="separator"`, `aria-orientation="vertical"`, 이름 `PDF와 원문 폭 조정`, `aria-valuenow` = PDF 영역 비율 %, `aria-valuemin` 25 · `aria-valuemax` 75)이 있다. 마우스·터치(pointer) 드래그, 또는 focus 후 ←/→(5%), Shift+←/→(10%), Home/End(최소/최대), Enter(기본 55%로 되돌림)로 조정한다. 각 영역은 최소 25%이며 비율은 이 브라우저에 기억한다. 모바일(<768px)은 기존처럼 `PDF`/`원문` 보기 전환이고 구분선이 없다.
- **문제 형식 (AC11):** 이 문서에서 가져와 확정(CONFIRMED)된 문제(문제 PDF import, `question_sources`의 import 출처)의 출처 블록은 원문 블록 대신 문제 카드 하나로 보인다: `N번` 번호, 유형, 발문, 보기 목록(`①` 등 보기 label 포함, 순서 = 등록된 보기 순서), 그리고 기본으로 접힌 `정답·해설 보기` disclosure. 정답·해설은 Workspace 구성원이 문제은행(QBANK-01)에서 이미 볼 수 있는 범위(공유 Viewer는 WS-VIEW-01의 발행 문제 범위)만이며 펼쳐야 보인다. 카드의 `원문 블록 보기`를 펼치면 원래 블록이 보이고 편집 권한자는 그 블록을 교정할 수 있다. 아직 초안(검토 전)인 문제, 생성 문제의 인용 출처, 직접 만든 문제는 문제 형식으로 바꾸지 않는다. 문제 목록을 불러오지 못해도 원문은 그대로 보인다.

## 수용 기준

### DOC-02-AC01

- **Given:** 해당 화면과 테스트용 데이터 및 권한이 주어진 상태
- **When:** 관련 조작/네트워크 요청을 수행
- **Then:** 파싱 완료 문서의 목차에서 장·절을 선택하면 PDF 페이지와 해당 원문 블록으로 이동한다.

### DOC-02-AC02

- **Given:** 해당 화면과 테스트용 데이터 및 권한이 주어진 상태
- **When:** 관련 조작/네트워크 요청을 수행
- **Then:** canonical 텍스트 블록을 수정·저장하면 draft revision을 새로 생성하지만 PDF 원본 파일은 변경하지 않는다.

### DOC-02-AC03

- **Given:** 해당 화면과 테스트용 데이터 및 권한이 주어진 상태
- **When:** 관련 조작/네트워크 요청을 수행
- **Then:** Draft를 발행하면 색인 작업 후 새 published revision이 검색에 반영된다.

### DOC-02-AC04

- **Given:** 해당 화면과 테스트용 데이터 및 권한이 주어진 상태
- **When:** 관련 조작/네트워크 요청을 수행
- **Then:** 재색인에 실패하면 이전 published revision 검색을 유지하면서 오류와 재시도 안내를 제공한다.

### DOC-02-AC05

- **Given:** 해당 화면과 테스트용 데이터 및 권한이 주어진 상태
- **When:** 관련 조작/네트워크 요청을 수행
- **Then:** 읽기 전용 사용자는 편집 UI와 쓰기 API가 차단된다. 공유 Viewer에게도 같은 제약 적용.

### DOC-02-AC06

- **Given:** 파싱 완료 문서를 데스크톱 폭에서 연 상태
- **When:** PDF 도구 막대의 `목차` 버튼으로 목차 panel을 접고 다시 펼친다
- **Then:** 목차는 왼쪽 floating panel에 있고 버튼의 `aria-expanded`가 상태를 알린다. 접으면 PDF와 원문 영역이 넓어지고, 다시 열면 장·절 선택이 AC01처럼 동작한다. 새로고침해도 마지막 펼침/접힘 상태가 유지된다.

### DOC-02-AC07

- **Given:** 여러 쪽짜리 문서를 열어 첫 쪽이 그려진 상태
- **When:** `다음 페이지`·`이전 페이지`·`현재 페이지` 입력으로 쪽을 여러 번 넘긴다
- **Then:** 현재 쪽의 다음 쪽은 넘기기 전에 이미 그려져 있고, 이동한 쪽의 canvas가 곧바로(1초 이내) 그려지며, 이미 본 쪽으로 돌아가도 마찬가지다. 쪽을 넘기는 동안 네트워크 요청이 하나도 없다(원본·서명 URL·원문 API·RSC; Next.js 링크 prefetch 제외). 원본 PDF는 화면을 연 뒤 한 번만 내려받는다.

### DOC-02-AC08

- **Given:** 여러 쪽짜리 문서를 연 상태
- **When:** PDF를 스크롤하거나 쪽을 넘긴다
- **Then:** `현재 페이지`가 보이는 쪽으로 바뀌고 원문 텍스트 영역이 그 쪽 묶음을 보이도록 스크롤한다. 블록을 편집하는 중에는 텍스트 영역이 움직이지 않는다.

### DOC-02-AC09

- **Given:** 파싱 완료 문서를 연 상태
- **When:** 원문 텍스트 영역을 본다
- **Then:** 블록이 쪽별 묶음(`N쪽` 제목)으로 모여 있고 각 묶음에는 그 쪽에서 시작하는 블록만 있다. 현재 쪽 묶음 제목이 `aria-current="page"`이다.

### DOC-02-AC10

- **Given:** 태블릿 이상 폭에서 문서를 연 상태
- **When:** PDF와 원문 사이 구분선을 pointer로 끌거나 키보드(←/→, Home/End)로 조정한다
- **Then:** 두 영역의 폭이 바뀌고 구분선의 `aria-valuenow`가 PDF 영역 비율을 알린다. 비율은 25–75% 안에 머물고 새로고침 뒤에도 유지된다.

### DOC-02-AC11

- **Given:** 문제 PDF를 가져와 일부 문제를 확정한 상태
- **When:** 그 문제 PDF의 문서 보기를 연다
- **Then:** 확정된 문제의 출처 블록은 문제 카드(번호·발문·보기 목록)로 보이고 정답·해설은 `정답·해설 보기`를 펼쳐야 보인다. 확정하지 않은 문제의 블록은 원문 블록 그대로이며, `원문 블록 보기`로 카드의 원래 블록을 볼 수 있다.
