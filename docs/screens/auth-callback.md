# AUTH-04 — 인증 콜백

**상태:** 확정 화면 요구사항 v1.3 · 2026-10-16
**Route:** `/auth/callback`
**연계 E2E:** `tests/e2e/auth/callback.spec.ts`

## 목적·레이아웃
- Next.js App Router 기반, 모바일/데스크톱 반응형 레이아웃과 Minimal Glass 디자인 시스템을 사용한다.
- 상태: 최초 로딩, 입력 검증, 처리 중, 성공, 실패, 빈 데이터, 권한 오류, 세션 만료를 명시적으로 처리한다.
- 입력 컴포넌트에 필수 라벨·설명·에러를 연결하고 키보드와 스크린리더에 대한 접근성을 보장한다.
- Supabase Auth를 사용하되 인증 경계와 리소스 인가는 FastAPI가 재검증한다.

## 수용 기준

### AUTH-04-AC01

- **Given:** 유효한 일회용 인증 코드를 세션으로 교환하고 허용된 내부 경로로 이동한다.
- **When:** 해당 조작·라우트 접근 또는 서버 API 요청
- **Then:** 유효한 일회용 인증 코드를 세션으로 교환하고 허용된 내부 경로로 이동한다.

### AUTH-04-AC02

- **Given:** next가 외부 URL 또는 프로토콜 상대 URL이면 무시하고 안전한 기본 경로를 사용한다.
- **When:** 해당 조작·라우트 접근 또는 서버 API 요청
- **Then:** next가 외부 URL 또는 프로토콜 상대 URL이면 무시하고 안전한 기본 경로를 사용한다.

### AUTH-04-AC03

- **Given:** 무효/만료 코드면 /auth/error로 이동하고 재시도 방법을 제시한다.
- **When:** 해당 조작·라우트 접근 또는 서버 API 요청
- **Then:** 무효/만료 코드면 /auth/error로 이동하고 재시도 방법을 제시한다.

## E2E-first 구현 규칙
- 해당 AC ID를 Playwright 시나리오로 먼저 작성하고 기대된 RED 실패를 확인한 뒤 구현한다.
- 성공/실패/권한 차단 결과는 실제 서버 응답에서도 보장되어야 하며 화면 조건만으로 대체하지 않는다.
