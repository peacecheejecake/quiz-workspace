# AUTH-05 — 비밀번호 재설정 요청

**상태:** 확정 화면 요구사항 v1.3 · 2026-10-16
**Route:** `/forgot-password`
**연계 E2E:** `tests/e2e/auth/forgot.spec.ts`

## 목적·레이아웃
- Next.js App Router 기반, 모바일/데스크톱 반응형 레이아웃과 Minimal Glass 디자인 시스템을 사용한다.
- 상태: 최초 로딩, 입력 검증, 처리 중, 성공, 실패, 빈 데이터, 권한 오류, 세션 만료를 명시적으로 처리한다.
- 입력 컴포넌트에 필수 라벨·설명·에러를 연결하고 키보드와 스크린리더에 대한 접근성을 보장한다.
- Supabase Auth를 사용하되 인증 경계와 리소스 인가는 FastAPI가 재검증한다.

## 수용 기준

### AUTH-05-AC01

- **Given:** 존재하거나 존재하지 않는 이메일 모두 동일한 성공 안내를 표시하여 계정 존재 유추를 막는다.
- **When:** 해당 조작·라우트 접근 또는 서버 API 요청
- **Then:** 존재하거나 존재하지 않는 이메일 모두 동일한 성공 안내를 표시하여 계정 존재 유추를 막는다.

### AUTH-05-AC02

- **Given:** 이메일 형식이 부정확하면 필드 오류만 표시하고 서버 메일 요청을 보내지 않는다.
- **When:** 해당 조작·라우트 접근 또는 서버 API 요청
- **Then:** 이메일 형식이 부정확하면 필드 오류만 표시하고 서버 메일 요청을 보내지 않는다.

### AUTH-05-AC03

- **Given:** 서버 실패·요청 과다
- **When:** 해당 조작·라우트 접근 또는 서버 API 요청
- **Then:** 서버 실패·요청 과다 시 민감정보 없는 재시도 안내를 표시한다.

## E2E-first 구현 규칙
- 해당 AC ID를 Playwright 시나리오로 먼저 작성하고 기대된 RED 실패를 확인한 뒤 구현한다.
- 성공/실패/권한 차단 결과는 실제 서버 응답에서도 보장되어야 하며 화면 조건만으로 대체하지 않는다.
