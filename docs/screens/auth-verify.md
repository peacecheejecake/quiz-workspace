# AUTH-03 — 이메일 인증 대기

**상태:** 확정 화면 요구사항 v1.3 · 2026-10-16
**Route:** `/auth/verify`
**연계 E2E:** `tests/e2e/auth/verify.spec.ts`

## 목적·레이아웃
- Next.js App Router 기반, 모바일/데스크톱 반응형 레이아웃과 Minimal Glass 디자인 시스템을 사용한다.
- 상태: 최초 로딩, 입력 검증, 처리 중, 성공, 실패, 빈 데이터, 권한 오류, 세션 만료를 명시적으로 처리한다.
- 입력 컴포넌트에 필수 라벨·설명·에러를 연결하고 키보드와 스크린리더에 대한 접근성을 보장한다.
- Supabase Auth를 사용하되 인증 경계와 리소스 인가는 FastAPI가 재검증한다.

## 수용 기준

### AUTH-03-AC01

- **Given:** 가입 후 Mailpit 이메일 링크로 검증하면 이메일 확인 상태가 되고 로그인 흐름에 복귀한다.
- **When:** 해당 조작·라우트 접근 또는 서버 API 요청
- **Then:** 가입 후 Mailpit 이메일 링크로 검증하면 이메일 확인 상태가 되고 로그인 흐름에 복귀한다.

### AUTH-03-AC02

- **Given:** 재전송 제한 시간 동안 연속 제출을 막고 사유를 표시한다.
- **When:** 해당 조작·라우트 접근 또는 서버 API 요청
- **Then:** 재전송 제한 시간 동안 연속 제출을 막고 사유를 표시한다.

### AUTH-03-AC03

- **Given:** 미인증 사용자가 보호 Workspace 라우트에 접근하면 차단한다.
- **When:** 해당 조작·라우트 접근 또는 서버 API 요청
- **Then:** 미인증 사용자가 보호 Workspace 라우트에 접근하면 차단한다.

## E2E-first 구현 규칙
- 해당 AC ID를 Playwright 시나리오로 먼저 작성하고 기대된 RED 실패를 확인한 뒤 구현한다.
- 성공/실패/권한 차단 결과는 실제 서버 응답에서도 보장되어야 하며 화면 조건만으로 대체하지 않는다.
